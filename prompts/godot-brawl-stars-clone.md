# Задача: аренный шутер 3×3 в духе Brawl Stars на Godot 4

## 0. Роль и режим работы

Ты — ведущий разработчик игр на Godot 4 (GDScript) и геймдизайнер мобильных аренных шутеров. Сделай **играбельный прототип** top-down шутера по механикам Brawl Stars: короткие матчи, управление «двумя стиками», три заряда с перезарядкой, суперспособность, кусты, разрушаемые стены, боты.

Режим работы определи сам:
- **Агент** (есть доступ к файлам и терминалу: Claude Code, Cursor, Codex и т. п.). Создавай файлы прямо в проекте. Этапы 0–4 выполняй подряд; после каждого прогоняй проверки из раздела 14, исправляй ошибки и, если проект под git, делай коммит «Этап N: …». После этапа 4 остановись и отчитайся. Этапы 5+ — по команде.
- **Чат** (доступа к файлам нет). Один ответ — один этап или его часть. Начни с этапа 0 и жди команды «дальше». Формат ответа — в разделе 14.

Приоритеты (при конфликте побеждает верхний):
1. Проект открывается в Godot и запускается без ошибок в Output и Debugger.
2. Геймплей точно соответствует спецификации: числа, правила, управление.
3. Архитектура расширяемая: нового бойца или режим можно добавить, не переписывая ядро.
4. Визуальная полировка.

Не задавай уточняющих вопросов, если ответ есть в спецификации. Если чего-то нет — прими решение в духе Brawl Stars, запиши его одной строкой в `docs/DECISIONS.md` и продолжай. Не пиши, что код запускался или тесты прошли, если ты этого не делал.

## 1. Объём

**MVP (этапы 1–4):**
- Режим «Захват кристаллов» 3×3: игрок и 2 бота-союзника против 3 ботов.
- 4 оригинальных бойца с разными типами атаки (раздел 5).
- Управление: клавиатура с мышью и геймпад (сенсор — на этапе 5).
- Цикл экранов: меню → выбор бойца → матч → результаты → меню.

**Дальше:** этап 5 — сенсорное управление и полировка; этап 6 — режим «Столкновение» (каждый сам за себя, 10 бойцов, ядовитый газ). Этап 7 — только по отдельной команде: гаджеты, прогрессия, сетевая игра.

**Не делаем:**
- Названия, персонажей, логотипы, графику, звуки и музыку Supercell / Brawl Stars. Копируем только механики, всё остальное — оригинальное. Рабочее название игры — «Gem Rumble».
- Внешние ассеты и плагины: вся графика — плейсхолдеры, нарисованные кодом.
- C#, монетизацию, аккаунты, серверы.

**Каким должен быть результат по ощущениям:**
- Отклик: действие происходит в тот же физический тик, что и ввод.
- Читаемость: цвета команд, полоски HP и индикатор прицела видны всегда.
- Матч длится 2–3 минуты, возрождение быстрое.
- Кусты, стены и вода реально влияют на тактику.

## 3. Архитектура

### 3.1. Боец: одна сцена + данные + контроллер

- `Brawler` (`CharacterBody2D`, `motion_mode = MOTION_MODE_FLOATING`) — одна сцена для всех бойцов. Бойцы отличаются **только данными** (`BrawlerData`) и типом атаки (`AttackData.pattern`).
- Компоненты (дерево ниже) — дочерние узлы с одной обязанностью. Логика компонента — в методе `tick(delta: float)`, его вызывает боец из `_physics_process`. Компоненты не обращаются к автозагрузкам: о событиях они сообщают своими сигналами, а в `Events` их пробрасывает боец. Так компоненты можно тестировать без сцены.
- **Боец не читает `Input`.** Контроллер каждый физический тик заполняет `BrawlerInput` (`RefCounted`):
  - `move: Vector2` — длина ≤ 1;
  - `aim: Vector2` — направление прицела, `Vector2.ZERO` — не целится;
  - `aim_distance: float` — для навесных атак, в px;
  - `attack_pressed`, `super_pressed`, `auto_aim: bool` — одноразовые флаги, боец сбрасывает их после обработки.
- Контроллеры: `PlayerController` (клавиатура, мышь, геймпад, сенсор) и `BotController` (ИИ). Позже `NetworkController` добавляется без изменений бойца.

```
Brawler (CharacterBody2D) — корень не вращается
├─ CollisionShape2D            CircleShape2D радиуса тела
├─ Hurtbox (Area2D)            слой hurtboxes, CircleShape2D радиуса хитбокса
├─ HealthComponent, AmmoComponent, SuperComponent (Node)
├─ AttackExecutor (Node)
├─ Visual (Node2D)             тело и «ствол»; поворачивается только ствол
├─ AimIndicator (Node2D)
├─ StatusBar (Node2D)          HP, заряды, счётчик кристаллов или кубов
└─ Controller (Node)           PlayerController или BotController, назначает режим при спавне
```

### 3.2. Данные (`Resource`)

- `AttackData`: `pattern` (enum `SPREAD`, `BURST`, `LOBBED`, `DASH`), `damage: int`, `projectile_count: int`, `spread_deg`, `burst_interval`, `range_tiles`, `projectile_speed_tiles`, `projectile_radius_tiles`, `aoe_radius_tiles`, `flight_time`, `knockback_tiles`, `destroys_walls: bool`, `super_charge_per_hit`.
- `BrawlerData`: `id: StringName`, `display_name`, `role`, `description`, `color: Color`, `max_hp: int`, `move_speed_tiles`, `max_ammo: int = 3`, `reload_time`, `attack_cooldown`, `body_radius_tiles`, `hurtbox_radius_tiles`, `attack: AttackData`, `super_attack: AttackData`.
- Бойцы лежат в файлах `brawlers/data/<id>.tres`, атаки внутри — как `sub_resource`. Образец формата (показана часть полей):

```ini

[ext_resource type="Script" path="res://core/data/brawler_data.gd" id="1_brawler"]
[ext_resource type="Script" path="res://core/data/attack_data.gd" id="2_attack"]

[sub_resource type="Resource" id="Resource_attack"]
script = ExtResource("2_attack")
pattern = 0
damage = 300
projectile_count = 5
spread_deg = 30.0
range_tiles = 7.5
projectile_speed_tiles = 14.0
super_charge_per_hit = 0.065

[resource]
script = ExtResource("1_brawler")
id = &"buckshot"
display_name = "Картечь"
max_hp = 3600

```

### 3.3. События

Автозагрузка `Events` содержит только сигналы, без состояния: `brawler_damaged(target, amount, source)`, `brawler_died(victim, killer)`, `brawler_respawned(brawler)`, `super_ready(brawler)`, `wall_destroyed(cell: Vector2i)`, `gems_changed(team, count)`, `countdown_changed(team, seconds_left)`, `match_started()`, `match_ended(result: Dictionary)`. Правило: вниз по дереву — вызовы методов, вверх — сигналы, между системами — `Events`.

### 3.4. Слои коллизий

Битовые маски продублируй константами в `C`.

| Слой | Кто на нём | Кто его проверяет |
|---|---|---|
| 1 walls | стены `#` и `X`, ящики `P`, невидимая граница карты | тела бойцов (маска), лучи снарядов, прямая видимость ботов |
| 2 water | вода `~` | тела бойцов (маска); снаряды — нет |
| 3 brawlers | тела бойцов | никто: бойцы проходят сквозь друг друга, как в оригинале |
| 4 hurtboxes | `Area2D`-хитбоксы бойцов, манекенов, ящиков | снаряды, взрывы, рывок, подбираемые предметы |
| 5 pickups | кристаллы и кубы силы (`Area2D` с маской hurtboxes) | — |

Маска тела бойца — walls и water. Дружественного огня нет: проверяй `team` в коде, а не слоями.

### 3.5. Команды и видимость

- `team: int`. «Захват кристаллов»: 0 — синие (всегда команда игрока, база снизу), 1 — красные. «Столкновение»: у каждого своя команда 0–9. Ящики — `team = -1` (урон проходит от всех). Манекены тренировки — команда 1.
- На вопрос «видит ли команда T цель X» отвечает одна функция — `VisibilitySystem.is_visible_to(target, team) -> bool`. Её используют отрисовка, автоприцел и боты (боты не читерят).

## 4. Базовые механики

**Движение.** `velocity = input.move * speed`, затем `move_and_slide()`. Боец смотрит туда, куда целится, а если не целится — по направлению движения.

**Заряды (патроны).** До 3 зарядов, хранятся как `float` от 0 до 3. Перезарядка идёт непрерывно (`+delta / reload_time`, пока не полно; частичный прогресс не теряется). Атака требует ≥ 1.0 и списывает 1.0. Между атаками — минимум `attack_cooldown`; пока идёт очередь (`BURST`), новая атака невозможна.

**Супер.** Шкала 0..1. Каждое попадание **обычной атакой** по врагу или ящику добавляет `super_charge_per_hit`. На 1.0 — сигнал `super_ready`, свечение бойца и кнопки. Применение обнуляет шкалу. После смерти шкала сохраняется.

**Регенерация.** Если боец 3 с не атаковал и не получал урон, он плавно лечится на 13% max HP в секунду.

**Урон и смерть.** Любой урон проходит через `take_damage(amount: int, source: Node)`. Эффекты: белая вспышка 0.08 с и всплывающая цифра. При HP ≤ 0 сигнал `died` испускается ровно один раз, боец отключается (скрыт, коллизии выключены через `set_deferred`), дальше решает режим.

**Отбрасывание.** Сдвиг на `knockback_tiles` за 0.2 с через `move_and_collide` (сквозь стены нельзя), не больше одного раза на цель за одну атаку. На это время управление цели заблокировано.

**Возрождение (3×3).** Через 3 с на случайной точке спавна своей команды: полные HP и заряды, 1.5 с неуязвимости (пульсирующий щит).

**Стены `#`** блокируют движение и снаряды. Разрушаются только атаками с `destroys_walls = true`; клетка становится проходимой, навигация ботов обновляется. **`X`** — неразрушаемая стена. За краем карты — невидимая неразрушаемая граница.

**Вода `~`** непроходима, но снаряды и навесные атаки летят над ней.

**Кусты `*`** проходимы. Боец считается в кусте, если клетка под его центром — куст (проверка по сетке карты, без `Area2D`). Такой боец невидим для вражеской команды, кроме двух случаев:
- любой боец этой вражеской команды ближе 2.5 тайла (видимость общая для команды);
- он атаковал или получил урон за последние 1.0 с.

Невидимый враг не рисуется вовсе и не может стать целью автоприцела. Себя и союзников в кусте игрок видит полупрозрачными (alpha 0.5).

**Автоприцел** (для атаки и для супера — со своей дальностью). Цель — ближайший видимый враг-боец в пределах дальности; для прямых снарядов в приоритете враг без стен на линии огня. Нет бойцов — ближайший ящик. Нет целей — атака в направлении взгляда.

**Индикатор прицела** (видит только игрок, пока целится): для прямых снарядов — полоса длиной в дальность; для веера — сектор; для навесной атаки — круг зоны поражения в точке падения (не дальше дальности); для рывка — полоса пути. Атака — белый с alpha 0.35, супер — жёлтый с alpha 0.45.

**Паттерны атак:**
- `SPREAD` — `projectile_count` снарядов одновременно, равномерно в секторе `spread_deg`.
- `BURST` — `projectile_count` снарядов подряд через `burst_interval`; направление фиксируется в момент выстрела.
- **Прямой снаряд** — `Node2D`, движется вручную в `_physics_process` и исчезает, пролетев дальность. Каждый тик: луч `intersect_ray` от старой позиции к новой по маске walls и `intersect_shape` круга снаряда по маске hurtboxes. Хитбоксы проверяй раньше стен: хитбокс ящика чуть больше его тела, и снаряд должен нанести ему урон, а не исчезнуть о стену. Попал во врага — урон, снаряд исчезает (одна цель — одно попадание). Попал в стену — снаряд исчезает; если `destroys_walls`, стена `#` разрушается, а снаряд летит дальше. Шаг за тик должен быть меньше радиуса хитбокса, иначе дели движение на подшаги.
- `LOBBED` — летит по параболе `flight_time` секунд в точку прицела над стенами и водой (визуально — смещение по Y и тень на земле). При падении — `intersect_shape` круга `aoe_radius_tiles` по маске hurtboxes: урон всем врагам в радиусе, стены не защищают. Если `destroys_walls` — разрушает стены `#` в радиусе.
- `DASH` — боец пролетает `range_tiles` со скоростью `projectile_speed_tiles`: ломает стены `#` на пути (если `destroys_walls`), останавливается о `X`, воду и край карты, наносит урон каждому врагу на пути один раз и отбрасывает его.

## 6. Режимы

### 6.1. «Захват кристаллов» (MVP)

- Карта `gem_grab_01`, 3×3, игрок всегда в синей команде (спавн снизу).
- Перед стартом — отсчёт «3, 2, 1, Бой!», управление заблокировано. Лимит матча — 2:30.
- Шахта `G` каждые 7 с выбрасывает кристалл: он вылетает (tween 0.3 с) в случайную проходимую клетку в радиусе 1.5 тайла.
- Кристалл подбирается касанием хитбокса. Над бойцом — его число кристаллов. Счёт команды — сумма кристаллов её бойцов.
- Погибший роняет все кристаллы: они разлетаются по свободным клеткам в радиусе 1.5 тайла, подобрать их можно через 0.5 с.
- Когда у команды ≥ 10 кристаллов и строго больше, чем у соперника, идёт отсчёт 15 с (крупные цифры цвета команды вверху по центру). Условие нарушилось — отсчёт сбрасывается. Дошёл до нуля — эта команда победила. Логика отсчёта — отдельный класс `GemCountdown` без зависимостей от сцены.
- Время вышло — побеждает команда с бо́льшим счётом, при равенстве — ничья.
- Результаты: победа, поражение или ничья; по каждому бойцу — убийства, смерти, урон, собранные кристаллы; «звезда матча» — у кого больше очков (убийство — 2, кристалл — 1, каждые 1000 урона — 1).

### 6.2. «Столкновение» (этап 6)

- Карта `showdown_01` 40×40, 10 бойцов (игрок и 9 ботов), каждый сам за себя. Точек спавна `S` — 12, используются 10 случайных.
- Ящик `P`: 4000 HP, `team = -1`, после разрушения оставляет куб силы. Куб: +400 к max HP (и лечит на 400), +10% урона (прибавки складываются). Число кубов видно над головой.
- Погибший роняет все свои кубы (минимум один). Возрождения нет. Место погибшего — число оставшихся в живых (без него) плюс один.
- Газ: с 40-й секунды безопасная зона-квадрат сужается на 1 тайл с каждой стороны каждые 5 с, пока не останется 6×6 в центре. В газе — 1000 урона в секунду (тиками по 0.5 с). Газ рисуется полупрозрачной зелёной заливкой вне зоны.
- Побеждает последний выживший; экран результатов показывает место игрока.

## 7. Карты

Карта — ресурс `MapLayout` (`maps/layouts/<id>.tres`) с полями `id`, `display_name`, `rows: PackedStringArray`, `mirror_x: bool`, `mirror_y: bool`. Карты не храни в `.txt`: такие файлы не попадают в экспорт без фильтра.

`MapBuilder` строит карту в рантайме:
- проверяет, что все строки одной длины, иначе вызывает `push_error` с номером строки;
- `mirror_x`: дописывает к каждой строке её зеркальную копию; `mirror_y`: дописывает к массиву строк его же в обратном порядке;
- стена — `StaticBody2D` + `CollisionShape2D` на каждый тайл; вода — `StaticBody2D` на слое water; ящик — `StaticBody2D` на слое walls плюс `Hurtbox` на 10% больше тела; кусты, шахта и спавны — по легенде;
- отдаёт `AStarGrid2D` для ботов (`diagonal_mode = DIAGONAL_MODE_ONLY_IF_NO_OBSTACLES`; стены, вода, ящики — solid) и методы `cell_to_world()`, `world_to_cell()`, `get_tile()`, `is_walkable()`, `get_spawns()`. Порядок важен: сначала `region`, `cell_size` и `update()`, потом `set_point_solid()` — `update()` сбрасывает препятствия.

## 8. ИИ ботов

Бот управляет бойцом **только через `BrawlerInput`** и подчиняется тем же правилам: видимость, заряды, перезарядка.

- Решения — 5 раз в секунду (таймер 0.2 с, у каждого бота случайный сдвиг фазы). Движение по текущему пути — каждый физический тик.
- Путь — `AStarGrid2D` по клеткам; пересчёт не чаще раза в 0.5 с или при смене цели. Если цель стоит на непроходимой клетке (ящик) — путь к соседней проходимой. Если до точки через одну нет стен (`intersect_ray`), срезай угол.
- Анти-застревание: если бот пытается идти, но за 1 с сместился меньше чем на 0.2 тайла, пересчитай путь; повторилось — полсекунды иди в случайную сторону.

Состояния:
1. **OBJECTIVE** — цель режима. «Захват кристаллов»: подобрать ближайший свободный кристалл; если у бота есть кристаллы и у его команды идёт отсчёт — держаться у своей базы и не лезть в бой; если отсчёт у соперника — атаковать вражеского носителя с наибольшим числом кристаллов. «Столкновение»: ломать ближайший ящик, подбирать кубы, держаться в безопасной зоне.
2. **ENGAGE** — есть видимый враг ближе 1.3 × дальности атаки. Цель выбирается по оценке: ближе, меньше HP, несёт кристаллы или кубы (вес ×2). Держать дистанцию ≈ 0.8 × дальности (танк — вплотную) и стрейфить перпендикулярно, меняя сторону каждые 0.6–1.2 с. Стрелять, если цель в дальности, есть заряд и (для прямых снарядов) линия огня свободна.
3. **RETREAT** — HP ниже порога: уходить от ближайшего врага к своей базе или в ближайший куст и не стрелять, чтобы пошла регенерация. Вернуться в бой при HP > 80%.
4. **Супер** применять сразу, как он заряжен и цель в дальности супера (Молоту — с дистанции ≤ 5 тайлов).

Сложность выбирается в настройках, по умолчанию — «Нормальная»:

| Параметр | Лёгкая | Нормальная | Сложная |
|---|---|---|---|
| Реакция на появившегося врага, с | 0.6 | 0.35 | 0.15 |
| Разброс прицела | ±15° | ±8° | ±3° |
| Упреждение по скорости цели | нет | нет | да |
| Порог отступления, % HP | 25 | 35 | 45 |
| Бережёт последний заряд | нет | да | да |

## 9. Управление

Действия регистрируй **в коде** — в автозагрузке `InputSetup` (`InputMap.add_action` и `InputMap.action_add_event`, если действия ещё нет). Не пиши сериализованные `InputEvent` в `project.godot` вручную.

| Действие | Клавиатура и мышь | Геймпад |
|---|---|---|
| движение `move_left/right/up/down` | WASD и стрелки | левый стик |
| прицел | курсор мыши | правый стик (отклонение > 0.3) |
| атака `attack` | ЛКМ: зажать — индикатор, отпустить — выстрел в сторону курсора | RT: в сторону правого стика, если он отклонён, иначе автоприцел |
| автоатака `auto_attack` | Пробел | — |
| супер `use_super` | ПКМ — как ЛКМ; E — супер с автоприцелом | LT или RB — как RT |
| пауза `pause` | Esc | Start |
| отладка (только debug-сборка) | F1 — FPS и пути ботов; 1–4 — сменить бойца в тренировке | — |

- Движение — через `Input.get_vector(...)`.
- Атаки на ПК обрабатывай в `_unhandled_input`, **а не** опросом `Input.is_action_*`: иначе клик по кнопке интерфейса вызовет выстрел.
- Для навесных атак `aim_distance` — расстояние до курсора (на геймпаде и сенсоре — отклонение стика × дальность), но не больше дальности.

**Сенсорное управление (этап 5).** Включается, если `DisplayServer.is_touchscreen_available()`, либо вручную в настройках.
- Левая половина экрана — «плавающий» джойстик движения: появляется в точке касания.
- Справа — джойстик атаки: тянешь — прицел с индикатором, отпускаешь — выстрел. Короткий тап (< 0.2 с, сдвиг < 15% радиуса) — автоприцел. Вернул палец в центр — отмена.
- Рядом — джойстик супера с той же логикой; активен и светится только при заряженном супере.
- Мультитач: отслеживай `index` пальца в `InputEventScreenTouch` и `InputEventScreenDrag`.
- При включённом сенсоре игнорируй мышиные действия атаки: Godot эмулирует мышь из касаний, иначе выстрелы задвоятся.

## 10. Интерфейс

UI — на `CanvasLayer`. Узлы, к которым обращается код, помечены уникальными именами (`%Name`). Все тексты — на русском.

**Над бойцами:** полоска HP с числом (своя — зелёная, союзников — синяя, врагов — красная) и имя. У игрока под HP — 3 сегмента зарядов, которые заполняются по мере перезарядки. Там же — счётчик кристаллов или кубов и щит неуязвимости.

**HUD матча:** вверху по центру — таймер. «Захват кристаллов»: счёт синих слева, красных справа, крупный отсчёт 15 с. «Столкновение»: «Осталось бойцов: N». Внизу справа — круговая шкала супера, пульсирует при готовности. После смерти игрока — затемнение и «Возрождение через 3… 2… 1».

**Экраны:**
1. Главное меню: крупная карточка выбранного бойца; кнопки «Играть» (большая, жёлтая), «Бойцы», переключатель режима, «Настройки», «Выход».
2. Выбор бойца: 4 карточки — цвет, имя, роль, HP, урон атаки, дальность, описание супера.
3. Экран «VS» на 1.5 с перед матчем: составы команд.
4. Пауза (Esc): «Продолжить», «Настройки», «Сдаться» (выход в меню). Игра останавливается через `get_tree().paused`.
5. Результаты: итог, таблица статистики, «звезда матча», кнопки «Ещё раз» и «В меню».
6. Настройки: громкость, сложность ботов, сенсорное управление (вкл / выкл / авто), показ FPS. Хранятся в `user://settings.cfg` (`ConfigFile`).

## 11. Графика, камера, эффекты, звук

Вся графика — плейсхолдеры в `_draw()`, собранные в узле `Visual` каждой сущности, чтобы позже заменить их спрайтами, не трогая логику.
- Бойцы — фигуры из раздела 5 с обводкой цвета команды (синий `#3B82F6`, красный `#EF4444`), у игрока — ещё кольцо под ногами. Направление показывает повёрнутый «ствол».
- Стена — скруглённый квадрат со светлой «верхней гранью» и тенью (иллюзия высоты). Куст — зелёное «облако»; кусты в радиусе 1.5 тайла от игрока полупрозрачные (alpha 0.45), чтобы он видел себя и союзников. Вода — синяя заливка с медленной волной. Шахта — тёмный круг с фиолетовым свечением. Кристалл — фиолетовый ромб с бликом.
- Эффекты: вспышка попадания (`modulate`, 0.08 с); цифры урона (tween вверх с исчезанием, 0.6 с); вспышка у ствола; след снаряда; кольцо взрыва (расширяющийся круг, 0.3 с); частицы смерти (`CPUParticles2D`); тряска камеры при супере рядом с игроком или сильном уроне по нему (до 6 px, 0.2 с); жёлтая пульсация бойца с заряженным супером.

**Камера** — `Camera2D`, zoom 1.0 (в кадре ≈ 30×17 тайлов). Следует за игроком со сглаживанием (`position_smoothing_enabled`) и смещением до 1.5 тайла в сторону прицела. Если карта уже экрана, X камеры фиксирован по центру карты; иначе X, как и Y, ограничен краями карты. Ограничение считай сам: стандартные `limit_*` прижимают узкую карту к краю вместо центрирования. Когда игрок погиб, камера остаётся на месте его смерти; после возрождения плавно переезжает к спавну.

**Звук.** Автозагрузка `Audio` с методом `play_sfx(sfx_name: StringName)`: проигрывает `res://audio/sfx/<sfx_name>.ogg`, если файл есть (`ResourceLoader.exists`), иначе молча ничего не делает. Вызовы расставь везде: выстрел, попадание, взрыв, смерть, кристалл, супер готов, победа, поражение. Звуки (например, CC0) пользователь добавит сам.

## 12. Правила кода и ловушки Godot 4

**Стиль:**
- Статическая типизация везде: `var hp: int = 0`, `func take_damage(amount: int, source: Node) -> void:`, типизированные массивы `Array[Brawler]`.
- `class_name` — для переиспользуемых классов; имена не совпадают со встроенными классами Godot (`Timer`, `Camera2D`, `Area2D` и т. п.) и с именами автозагрузок.
- Файлы, функции, переменные — `snake_case`; классы и узлы — `PascalCase`; константы — `UPPER_SNAKE_CASE`; приватное — с `_`.
- Отступы — табы (как в редакторе Godot), без смешивания с пробелами.
- Никаких «магических чисел»: только `C`, `@export` или `.tres`.
- Скрипт — не длиннее ~300 строк, иначе дели.
- В обязательной функциональности — никаких `TODO` и заглушек. Комментарии короткие, по-русски, объясняют «зачем», а не «что».
- Всё случайное в матче — через один `RandomNumberGenerator` матча (для автотеста задаётся seed).

**Только API Godot 4** — нейросети часто пишут синтаксис Godot 3:

| Нельзя (Godot 3) | Нужно (Godot 4) |
|---|---|
| `KinematicBody2D`, `move_and_slide(vel)` | `CharacterBody2D`, `velocity = …` и `move_and_slide()` |
| `export var`, `onready var`, `tool` | `@export var`, `@onready var`, `@tool` |
| `yield(obj, "sig")` | `await obj.sig` |
| `connect("sig", self, "_m")` | `sig.connect(_m)`, испускание — `sig.emit()` |
| `instance()`, `change_scene("…")` | `instantiate()`, `change_scene_to_file("…")` |
| `update()` для перерисовки | `queue_redraw()` |
| `rand_range`, `deg2rad`, `stepify`, `linear_interpolate`, `clamped` | `randf_range`, `deg_to_rad`, `snappedf`, `lerp`, `limit_length` |
| `Position2D`, узел `YSort`, `Tween.new()` + `interpolate_property` | `Marker2D`, свойство `y_sort_enabled`, `create_tween().tween_property()` |
| `RectangleShape2D.extents` | `size` — полный размер, а не половина |
| `OS.get_ticks_msec()`, `File`, `Directory` | `Time.get_ticks_msec()`, `FileAccess`, `DirAccess` |
| `intersect_ray(from, to)` | `intersect_ray(PhysicsRayQueryParameters2D.create(from, to, mask))` |
| `BUTTON_LEFT`, `scancode` | `MOUSE_BUTTON_LEFT`, `keycode` / `physical_keycode` |
| `smoothing_enabled` у `Camera2D` | `position_smoothing_enabled` |
| `setget` | свойство с блоками `set(value):` и `get:` |

**Ловушки, которые ломают запуск:**
1. `:=` не выводит тип из `Variant`: `var v := dict["k"]`, `var m := max(a, b)`, `var n := node.get("x")` — ошибка парсера. Указывай тип явно; вместо `max`/`min`/`clamp` — `maxf`, `maxi`, `minf`, `mini`, `clampf`, `clampi`.
2. Физическое состояние нельзя менять внутри `body_entered`, `area_entered` и других физических колбэков (`monitoring`, `disabled` у шейпа, добавление `Area2D` или тел) — будет ошибка «flushing queries». Используй `set_deferred()` / `call_deferred()`; например, так должны выпадать кристаллы при смерти.
3. Запросы `intersect_shape` / `intersect_ray` по умолчанию не видят `Area2D` — для хитбоксов ставь `collide_with_areas = true`.
4. `get_nodes_in_group()` возвращает `Array[Node]`: приводи элементы через `as`, не присваивай массив напрямую в `Array[Brawler]`.
5. Цели умирают: перед обращением к чужому объекту проверяй `is_instance_valid()`; после `await` проверяй, что узел ещё в дереве.
6. `%Name` работает, только если у узла в `.tscn` стоит `unique_name_in_owner = true`. Каждый `$Путь` и `%Имя` в коде обязан существовать в сцене.
7. `get_global_mouse_position()` вызывай у узла в мире (например, у бойца), а не у UI и не у простого `Node`.
8. `Area2D` без дочернего `CollisionShape2D` с назначенным `shape` ничего не обнаруживает. Слои и маски задавай константами из `C`.
9. `.tscn` и `.tres`: `format=3`; **не выдумывай `uid`** — не указывай его вовсе; `load_steps` можно опустить; файлы `.uid` не создавай — их сгенерирует редактор. Сцены держи простыми, динамическое (карта, списки в UI, эффекты) создавай кодом.
10. Частицы — только `CPUParticles2D` (гарантированно работают в Compatibility).
11. Не объявляй свойства и методы с именами встроенных (`name`, `position`, `scale`, `owner`, `visible`, `show`) — получишь ошибку или затенение.
