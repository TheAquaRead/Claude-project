# Быстрый генератор качественных сайтов через API

Одинаковый текст пользователя не даёт одинаковых условий сравнения: системный промпт, модель, инструменты, изображения и проверка браузером — части результата. Переключатель reasoning влияет на вычисления, но не заменяет художественное направление. Соответствие другой модели и срок 120 секунд нельзя гарантировать настройкой.

## Стартовая конфигурация

Responses API; точный model ID из вашего аккаунта; reasoning.effort = low. Сравните medium на тех же заданиях. Streaming улучшает время до первого видимого результата, но сам по себе не ускоряет завершение. Не выставляйте искусственно маленький max_output_tokens: в лимит входят также reasoning tokens. Начальная величина для полноценной страницы — 16000, затем настройте по фактическому расходу и длине страницы. Не передавайте temperature без проверки совместимости выбранной модели и reasoning.

Храните ключ только на сервере. Ни браузер, ни сгенерированный сайт не должны получать API-ключ. Подписка ChatGPT и API — разные продукты; доступность модели и инструменты нужно проверять в API-аккаунте.

## Постоянная инструкция генератору

```text
Ты проектируешь и реализуешь законченные сайты. Результат должен выглядеть как работа дизайнера и разработчика, а не как стартовый шаблон.

До кода выбери цель страницы, визуальный характер, пару шрифтов с поддержкой языка, масштаб заголовков, ширину контента и роль главного изображения. Не пиши длинное рассуждение: сразу реализуй выбор.

Следуй приложенному визуальному референсу по качеству композиции, типографики, плотности информации и работе с изображениями. Не копируй неподтвержденные факты и чужой бренд. Не своди все задачи к одному тёмному шаблону. Стиль должен соответствовать теме и аудитории.

Первый экран: ясное предложение, выразительный заголовок с осмысленными переносами, одно главное действие и изображение, созданное или выбранное под композицию. Все следующие разделы добавляют конкретное содержание. Не повторяй абстрактные лозунги. Чередуй уместные формы подачи: прайс, пояснение процесса, фотографии, ответы на вопросы, форма.

Используй согласованные SVG-иконки, а не случайные символы Unicode. Шрифты должны поддерживать кириллицу. Контролируй иерархию размеров, длину строк, контраст, отступы и мобильные переносы.

Анимация: короткое появление при прокрутке, понятные состояния кнопок и переходы интерактивных блоков. Не скрывай обязательный контент навсегда при ошибке анимации. Поддержи prefers-reduced-motion, клавиатуру и видимый фокус.

Каждая кнопка выполняет действие. Формы валидируют ввод. Не показывай «запись подтверждена», если сервер реально не создал бронь. Не придумывай адреса, отзывы, статистику, сотрудников и гарантии. Неизвестные данные не должны превращаться в правдоподобные факты.

Если есть инструменты, запусти создание нужных изображений сразу после короткого брифа и продолжай писать код, пока они генерируются. Используй возвращённые файлы/URL. Не выдумывай пути к несуществующим изображениям.

Заверши реализацию, проверь страницу на ширине 1440 и 390 px, отсутствие горизонтальной прокрутки, загрузку шрифтов/изображений и главный пользовательский сценарий. Посмотри скриншот и исправь конкретные дефекты. Не заменяй визуальную проверку заявлением «дизайн премиальный».

Возвращай готовые файлы и короткий отчёт: что сделано, что проверено, какие интеграции ещё не подключены. Не выдавай макет за работающий бизнес-сервис.
```

## Что должен предоставить ваш AI-сервис

1. Исполнение кода в изолированной среде: запись файлов, сборка, проверка JS.
2. Инструмент генерации или поиска изображений. Сам API-ключ не подключает инструменты этого чата. Можно использовать встроенную генерацию изображений при поддержке модели либо собственный tool/backend.
3. Браузер со снимками экрана и передачей снимка модели для исправления. Одних DOM-проверок недостаточно для оценки внешнего вида.
4. Preview/хостинг с настоящей ссылкой. Не возлагайте создание инфраструктуры на каждый запрос модели.
5. Сохранённые дизайн-инструкции и проверенные стартовые компоненты, передаваемые в каждом новом чате. Это воспроизводимая «память», которую контролирует ваше приложение.

## Минимальный запрос Python

```python
import os
from openai import OpenAI

client = OpenAI()  # OPENAI_API_KEY на сервере
response = client.responses.create(
    model=os.environ['OPENAI_MODEL'],  # точный поддерживаемый API model ID
    reasoning={'effort': 'low'},
    instructions=DESIGN_SYSTEM_PROMPT,  # текст постоянной инструкции выше
    input=[{
        'role': 'user',
        'content': [
            {'type': 'input_text', 'text': USER_BRIEF},
            {'type': 'input_image', 'image_url': REFERENCE_IMAGE_URL},
        ],
    }],
    max_output_tokens=16000,
)
print(response.output_text)
```

Это запрос генерации текста/кода с референсом, а не готовый автономный агент. Чтобы модель действительно запускала браузер, создавала изображения и публиковала сайт, объявите инструменты и реализуйте цикл: запрос → tool call → выполнение на вашем сервере → tool result → продолжение. Имена и схемы ваших инструментов должны совпадать с реализацией. Для продолжения можно использовать previous_response_id; постоянные instructions передавайте снова, поскольку они не наследуются автоматически через previous_response_id.

## Как приблизиться к двум минутам

Используйте заранее установленный starter, зависимости, шрифты, UI-примитивы и готовую публикацию. Для простого лендинга достаточно HTML/CSS/JS без установки фреймворка. Запускайте изображения параллельно с кодом; не ждите их перед началом вёрстки. Храните библиотеку подходящих изображений как быстрый вариант. Просите готовую реализацию без длинного текстового отчёта.

Начальная цель бюджета: короткий дизайн-бриф → код и изображения параллельно → браузерная проверка → ограниченная правка. Это целевой процесс, не измеренная гарантия скорости. Генерация изображений, сборка, объём кода и очередь API могут вывести за пределы двух минут.

Не делайте каждый шаг отдельным новым чатом без контекста. В отдельную задачу передавайте конкретный asset-brief и ожидаемый формат результата. Контекст основного сайта сохраняйте. В текущей переработке использовалась асинхронная генерация изображения; субагенты не запускались.

## Как выбрать low или medium честно

Возьмите 10–20 одинаковых брифов и одинаковый набор инструментов. Сгенерируйте несколько результатов на low и medium с одним дизайн-промптом и теми же референсами. Сравнивайте вслепую: первый экран, типографика, содержание, мобильная версия, исправность сценариев. Записывайте полное время до рабочего preview, стоимость, долю ошибок и ручных исправлений. Сравнивайте p50 и p95, а не один удачный прогон. Если low не проходит ваш порог качества, используйте medium или усиливайте starter/референсы; не обещайте эквивалентность другой модели.
